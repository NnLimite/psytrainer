# Статус и что осталось сделать

## Готово и проверено

- Бэкенд: все 82 операции API, 80 тестов (SQLite и PostgreSQL), контрактный тест, сквозная проверка по HTTP.
- Миграции Alembic применяются вверх и вниз без расхождений с моделями.

## Чтобы запустить (блокирует старт)

- [ ] Ollama и скачанная Qwen 27-30B; точный тег в `PSY_OLLAMA_MODEL`; GPU виден в WSL; подобран `PSY_OLLAMA_NUM_CTX`
- [ ] Чистая БД (у вас уже есть своя схема и Alembic: мои миграции с ней конфликтуют)
- [ ] `.env` из `backend/.env.example`, заменённые секреты
- [ ] Первый администратор: `python -m app.cli create-user`
- [ ] 20-30 реплик вручную на реальной модели (русский язык, держит ли роль, задержка)

## Чтобы стало продуктом

- [ ] **Фронтенд**: экраны входа, конструктора, каталога, чата с панелью состояния, разбора, кабинета преподавателя
      (см. `frontend/README.md`)
- [ ] **Содержимое**: рубрика оценки (без неё оценку не запустить), 3-5 кейсов, расширенный справочник расстройств
- [ ] **Эксперт**: преподаватель или практикующий психолог проверяет кейсы, рубрику и коэффициенты `engine/state_engine.py`
- [ ] **Подписки**: реальный платёжный провайдер и проверка подписки перед сессией (сейчас подписки только записываются)
- [ ] **Данные и право**: текст согласия, политика хранения транскриптов, место хостинга, проверка требований
      к персональным данным (например, ФЗ-152) с юристом, процедура на случай кризиса студента
- [ ] **Прод**: HTTPS и домен, прокси без буферизации SSE, резервные копии БД, мониторинг, CI, Redis с хранением данных
- [ ] **Пилот**: договорённость с кафедрой, 5-10 студентов, 2-3 метрики успеха

внутри процесса API), правила для типа события `harmful_content`.
