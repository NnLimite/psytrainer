# PsyTrainer: бэкенд

FastAPI + PostgreSQL + Redis + Ollama. Реализует весь контракт `docs/openapi.yaml` (82 операции): аутентификация и SSO,
организации и группы, конструктор кейсов с версиями, сессии с ИИ-пациентом (SSE), состояние пациента, безопасность,
оценка по рубрикам, аналитика и отчёты, согласия и удаление данных, подписки, администрирование.

## Быстрый старт

```bash
cp .env.example .env            # задайте PSY_OLLAMA_MODEL (точный тег вашей Qwen 27B-30B) и секреты
docker compose up --build       # PostgreSQL, Redis, API на :8000 (миграции применяются при старте)
docker compose exec api python -m app.cli create-user --email admin@x.ru --role platform_admin
```

Документация API: `http://localhost:8000/docs`. Ollama по умолчанию берётся с хоста (`host.docker.internal:11434`):
сначала `ollama pull <тег модели>`.

Без Docker: `pip install -r requirements.txt`, поднять PostgreSQL, `alembic upgrade head`,
`uvicorn app.main:app_factory --factory --reload`.

Первого администратора создаёт только CLI: через API регистрация даёт роль студента. Преподавателей и студентов
организации добавляют приглашениями (`POST /organizations/{id}/invitations`) или SSO.

## Как устроен код

| Путь | Что делает |
|---|---|
| `app/engine/` | Ядро: модель случая, шкалы пациента, правила пересчёта, сборка промптов (без БД и сети) |
| `app/services/sessions.py` | Цикл реплики: разметка, триггеры, состояние, промпт, стриминг, запись, безопасность |
| `app/services/` | Доступ к объектам, оценка, аналитика, проверка кейсов, формулировка студента, задачи |
| `app/routers/` | HTTP-слой по группам эндпоинтов |
| `app/container.py` | Все внешние зависимости (БД, Redis, LLM, почта, SSO, платежи): подменяются в тестах |
| `app/models.py`, `alembic/` | Схема БД и миграции (0001 схема, 0002 справочник расстройств) |
| `docs/openapi.yaml` | Контракт. Генерируется из `docs/build_openapi.py`, сверяется с кодом тестами |

## Проверка

```bash
pip install -r requirements-dev.txt
pytest                              # 80 тестов на SQLite, около 20 секунд (все 82 маршрута вызываются тестами, покрытие строк около 93%)
python scripts/test_on_postgres.py  # встроенный PostgreSQL: миграции вверх-вниз-вверх, alembic check, те же тесты
python scripts/smoke_e2e.py         # реальный HTTP: uvicorn + PostgreSQL + OllamaClient против имитации Ollama
```

`tests/test_contract.py` сравнивает `docs/openapi.yaml` с тем, что генерирует FastAPI (операции, query-параметры,
коды успеха, тела запросов): код и контракт не разойдутся незаметно.

## Настройки (PSY_*, см. `app/config.py`)

| Переменная | Назначение |
|---|---|
| `PSY_DATABASE_URL`, `PSY_REDIS_URL` | БД и Redis. Без Redis (`PSY_REDIS_URL=`) работает память процесса: только для dev и одного процесса |
| `PSY_SECRET_KEY`, `PSY_PAYMENT_WEBHOOK_SECRET` | Секреты: в проде заменить, не короче 32 символов |
| `PSY_OLLAMA_MODEL`, `PSY_JUDGE_MODEL`, `PSY_OLLAMA_NUM_CTX` | Модель пациента; необязательная отдельная модель для оценки и подсказок; контекст |
| `PSY_USE_LLM_CLASSIFIER` | `false`: реплики студента размечает только эвристика (на реплику уходит на один вызов LLM меньше) |
| `PSY_COOKIE_SECURE` | `true` в проде (HTTPS) |
| `PSY_SSO_PROVIDERS` | JSON с настройками OIDC-провайдеров |
| `PSY_SMTP_*` | Почта; без неё письма пишутся в лог |
| `PSY_PLANS` | Планы подписки: имя и срок в днях |

## Что важно знать перед запуском

**Задержка ответа.** На каждую реплику студента уходит два вызова LLM: разметка, затем ответ пациента. На 27-30B
локально это заметно. Если задержка велика, задайте `PSY_JUDGE_MODEL` (небольшая быстрая модель для разметки) или
`PSY_USE_LLM_CLASSIFIER=false`. Ответ пациента идёт потоком, поэтому студент видит текст по мере генерации.

**Модель и русский язык.** Качество роли на русском не проверялось на реальной модели: проверьте на ваших диалогах
до пилота (набор реплик и критерии были в обсуждении выше). Тег модели в Ollama задаётся `PSY_OLLAMA_MODEL`.

## Ограничения и что не сделано

- **PDF-отчёты** не поддерживаются (422 `format_not_supported`); есть CSV и XLSX.
- **Фоновые задачи** выполняются внутри процесса API. При рестарте незавершённые задачи помечаются как неудачные.
  Для нескольких реплик или долгих задач нужна очередь (ARQ/Celery): интерфейс `JobRunner.submit` рассчитан на замену.
- **Экзамен без назначений.** Режим `exam` доступен студенту, который сам указал группу, где он состоит. Чтобы
  преподаватель действительно «открывал» экзамен, нужна сущность назначения (в контракте её нет).
- **Курсоры** в списках основаны на смещении: при вставке новых записей между запросами возможны дубли или пропуски.
- **Безопасность** — простые правила (первое лицо о нежелании жить, срыв роли пациента). Это первая линия, а не оценка
  риска: каждое событие должен просмотреть человек. Тип `harmful_content` в схеме есть, правил для него нет.
- **Лексическая оценка формулировки студента** (`match_score`, F1 по основам слов) грубая и подходит только как ориентир.
- **Справочник расстройств** — стартовая выборка из 16 записей. Проверьте и расширьте с клиницистом (новые записи через миграции).
- **SSO**: OIDC через userinfo-эндпоинт провайдера; SAML нет. Платежи: подключена заглушка `StubPayments`, реальный
  провайдер нужно реализовать (интерфейс `PaymentProvider`), подпись вебхука и идемпотентность уже есть.
- **Лимиты по IP**: за обратным прокси `request.client.host` равен адресу прокси. Запускайте uvicorn с `--proxy-headers`
  и ограничьте доверенные прокси. Вход ограничен отдельно по паре IP+email, чтобы группа за одним NAT не блокировала
  друг друга.
- **Персональные данные.** Транскрипты тренировок: персональные данные студентов. Перед пилотом нужны политика хранения,
  текст согласия и проверка требований законодательства (например, ФЗ-152) с юристом. Удаление данных реализовано
  (`DELETE /me`): транскрипты, состояние и формулировки стираются, оценки обезличиваются, учётная запись становится «надгробием».
- Проверено на PostgreSQL 16-совместимом сервере (встроенный pgserver) и SQLite. Клиент Redis проверен на fakeredis
  (`tests/test_kv.py`), но не на настоящем сервере: перед продом прогоните `smoke_e2e.py` с реальным Redis.
